# SKINNY-64-192 MITM：STP 搜索代码

此目录独立运行，无需 Gurobi 或 Python 第三方包。它迁移的是提供的 `skinny_LIN_DIS-main` 的当前 MILP 代码：五色、GreenCancellation v4、四类自由度、最多两次 LIN、匹配列凸包、相同轮切分与闭环，并加入可选的 GnD 着色扩展。`lin_rules.py` 保留原来的匹配秩与凸包检验，`CPMITM_LIN.py` 和 `model_stp.py` 保留原模型的建模逻辑；`stp_backend.py` 将其线性约束与 AND/OR 转为 SMT-LIB2 QF_BV；`solve_stp.py` 用 STP 可满足性查询完成最大化。

**版本差异：** `SKINNY_MITM_STP_Modeling.pdf` 的基线 A 使用绿色不降色、正向仅消耗红色、反向仅消耗蓝色；原代码和 `SKINNY_XOR_MILP_GreenCancellation_v4.pdf` 则允许绿色降色、两方向均可消耗红蓝两色。本实现以用户现有 Gurobi 模型及 v4 为准，属于前一文档中所说的宽松版本 B，**不是基线 A**。若要搜索基线 A，需要另行修改局部规则与对应记账并重新验证。

## 环境和运行

安装带 SMT-LIB2 命令行前端、支持 `get-value` 的 STP，确保 `stp --version` 可用；Python 3.9 或更新版本。STP 路径不在 PATH 时使用 `--stp /path/to/stp`。运行前请先切换到本目录：

```bash
cd /Users/grandkinez/Downloads/codex_skinny_lin/stp_skinny
python3 solve_stp.py --tr 23 --ini 2 --mat 12 --time 3600
python3 solve_stp.py --tr 23 --all --time 3600
python3 solve_stp.py --tr 23 --ini 2 --mat 12 --time 3600 --no-gnd
```

GnD 默认启用；`--no-gnd` 禁止所有猜测，以便搜索基线模型。`--time` 是每一组 `(ini, mat)` 的总秒数，而非每次调用；0 表示无限时。`--all` 枚举全部不同的起始轮与匹配轮。`--outdir` 指定输出目录，默认为当前目录下 `stp_solutions`。23 轮的运行时间和内存取决于 STP 版本及机器，不能保证在给定时限内找到解或证明最优。

只生成不带目标阈值的基础可行性模型：

```bash
python3 solve_stp.py --tr 23 --ini 2 --mat 12 --write-only
stp stp_solutions/TR23_ini2_mat12.smt2
```

正常求解找到解后，输出同名 `.smt2`（该可行解对应的完整阈值查询）、`.stp.out`（求解器原始输出）、`.json`（所有颜色和计数）及 `.txt`（报告）。`Result_TR*.json` 是所有切分的汇总。解的 JSON 包含 `gnd_counts`（`gb`、`gr`、`gbr` 三类总数）和 `gnd_at`（非零标签的位置、方向、猜测前后颜色与类型），文本报告也列出猜测信息。`optimal` 表示搜索的候选阈值均已通过 SAT/UNSAT 判断证明最优；`feasible_unproven` 表示有可行解但因为超时或 unknown 未证明最优；`unsat` 表示在模型约束下不存在正收益的可行着色，并不意味着删除正收益约束后也无着色；`unknown` 表示没有取得可行解且未完成证明。求解器错误会报错，不当作无解。重跑同一输出目录会覆盖同名结果。

## GnD 着色约束

GnD 插入正向 MC 的输入或逆向 MC 的输入，仅对原颜色为白色的 cell 开放。每个候选位置引入二元标签 \(g_B,g_R,g_{BR}\)，分别表示猜测成蓝、红、绿。记猜测前后颜色为 \((b,w,r)\) 和 \((b',w',r')\)，约束为：

\[
\begin{aligned}
g_B+g_R+g_{BR}&\le w,\\
b'&=b+g_B+g_{BR},\\
r'&=r+g_R+g_{BR},\\
w'&=w-g_B-g_R-g_{BR}.
\end{aligned}
\]

因此每个位置至多采用一种猜测；不猜测时颜色不变。猜测后的颜色进入既有 SKINNY MC 或逆 MC 规则，输出继续使用原有颜色变量。正向使用 `Z[r]` 作为猜测前输入，反向使用 `X[(r+1) % TR]`；匹配轮不插入 MC 猜测。`gBR` 使用普通绿色的蓝、红属性参与局部传播，供两侧计算使用。

**绿色只是此模型选择的着色抽象。** 两侧的具体猜测分量及其相容性须在攻击构造时明确并验证；不能仅凭绿色标签认为检查已经完成。该抽象能否与论文中的完整超位置状态和相容性条件等价，尚未证明。现有 ENC 平衡式保持不变，这依赖对外层固定猜测值及约束、内层构造中性字解空间的解释；各消耗约束是否独立且可满足仍需单独检查。

## 优化目标

令 \(G_B=\sum g_B\)、\(G_R=\sum g_R\)、\(G_{BR}=\sum g_{BR}\)，令 \(d_L=\alpha n_{\rm LIN}\)、\(\alpha=\log_2(3)/4\)。目标按 cell 数为单位：

\[
GObj=\min\{d_B-d_L-G_R-G_{BR},\;
d_R-d_L-G_B-G_{BR},\;
d_M-G_B-G_R-G_{BR}\}.
\]

其中 \(d_B,d_R,d_M\) 仍使用现有模型的定义。该目标是候选结构的搜索指标，不能单凭它得到完整密钥恢复攻击的时间、数据、内存和成功概率。

模型要求目标的三个分量都严格为正。由于其他项均为整数，且 \(0\le d_L\le 2\alpha<1\)，这等价于三条整数约束：

\[
d_B-G_R-G_{BR}\ge1,\qquad
d_R-G_B-G_{BR}\ge1,\qquad
d_M-G_B-G_R-G_{BR}\ge1.
\]

因此最小目标不低于 \(1-2\alpha>0\)。如果之后修改最大 LIN 次数或者单次 LIN 代价，需要重新推导这些整数约束。

## 结果解释与验证

`gnd_at` 保留每个非零猜测标签对应的 MC 轮（`round`）、输入状态所在轮（`state_round`）、cell 位置、方向和猜测前后颜色；反向时输入为 `X[(round+1)%TR]`，所以两个轮号可能不同。`gnd_counts` 给出三类猜测的总数。常规状态数组仍显示原有位置的颜色，须结合 `gnd_at` 区分 MC 输入位置猜测前后的颜色。构造具体攻击时，须检查各猜测与相应真实值或虚拟分量的关系、匹配方程及其独立性、LIN 分片条件与真实 S 盒行为，并对密钥编排和明密文边界做数值验证。局部规则的 SAT 解并不证明存在相应的真实攻击，也不保证这些假设或复杂度成立。


## 数值处理

候选阈值写作 `k−n0·α`，其中 `1 ≤ k ≤ 16`、`n0 ∈ {0,1,2}`。阈值检查使用上述扣除 GnD 猜测次数后的三个整数表达式；LIN 数 \(n\) 在 0、1、2 之间取值，因此可用整数比较精确处理阈值，显示值使用浮点数。

全部线性表达式使用 16 位有符号位向量，单个二元变量使用 1 位，其他变量按上界定宽并零扩展；支持 2–128 轮。读取求解结果后，程序还以 Python 整数重新核验所有变量范围和约束。

## 验证与适用范围

GnD 加入之前，本机未安装 STP，尚未直接用 STP 执行基线模型。对当时的基线用 Z3 的 SMT-LIB2 前端作兼容性检查时，2 轮 `(ini,mat)=(0,1)` 的最优目标为 16，与原 Gurobi 模型相同；把生成的全部变量赋值固定到原 Gurobi 模型后仍可行。原仓库的局部规则测试通过 19 项中的 17 项（2 项因依赖跳过）。这些历史检查不验证 GnD 扩展，也不是 23 轮的验证，不能证明两种求解器或两个模型在所有实例上的完全等价。

GnD 版本可用 `python3 -m unittest discover -s tests -v` 检查局部颜色转换、MC 接线、禁用模式及目标阈值。另将后端约束临时转换为 Gurobi 线性模型，验证了 2 轮禁用 GnD 的目标阈值 16 可行、4 轮分别强制存在 B、R、BR 猜测时的可行赋值，以及 5 轮存在反向 BR 猜测时的可行赋值；赋值经原后端的整数约束检查。此项交叉检查并非直接运行 STP，也没有证明 23 轮结果。

本模型的局部消耗与匹配秩不保证跨轮全局独立性；灰色匹配方程也未必构成有效过滤。LIN 的提示集合未被嵌入真实 S 盒求值，正向和逆向候选须结合 `lin_rules.py` 中的分片分别检查。最终仍需对输出方程、自由度和具体密钥恢复过程独立验证，不能仅凭 SAT 宣称得到真实攻击。
